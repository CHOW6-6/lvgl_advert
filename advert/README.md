# DEEPSEEK 广告机 · GEC6818

登录之后的**多功能广告机**：三页界面（播放 / 广告库 / 信息），素材从电脑推送过来，
板上自己轮播。初始三条广告就是给的三组「图片 + 视频」。

- 平台：GEC6818（S5P6818 / ARMv7 / Linux 3.4.39 / 800×480 32bpp fbdev + evdev 触摸）
- 界面：LVGL v8，纯软件渲染，没有 GPU
- 传输：自带一个 11KB 的 TCP 服务端 + 一个不依赖第三方库的 Python 客户端

## 2. 快速开始

### 2.1 编译

```bash
cd /home/user/code/lv_port_pc_vscode-release-v8

make            # 广告机主程序 → build/bin/demo
make ladpd      # 板端接收服务 → build/bin/ladpd
make deploy     # 广告机：demo + ladpd + 素材，一起推到板子并校时、重启服务
```

`make deploy` 做的事：`demo` 和 `ladpd` 落到 `/root/lvgl-demo/`，
`advert/data` 里的 `meta/`、`media/` 落到 `/root/lvgl-demo/advert/`，
再用本机时间校准板上时钟，最后重启 `ladpd`。

> **广告机和天气是两个独立的程序。**
> 天气是 `make weather` → `build/bin/weather`，`make deploy-weather` 单独部署，
> 不占用广告机的素材和 `ladpd`。两者共用一个 framebuffer，所以同一时刻只能跑一个。

### 2.2 启动网页上传服务（推荐给客户用）

```bash
make web                       # 默认 http://localhost:8080
make web PORT=9000             # 换端口
```

然后在**浏览器打开 http://localhost:8080**，选视频、选封面、填标题和备注，点上传就行。
转码、打包、CRC 校验、推流全在后台完成，页面上有进度条。

这个服务跑在**电脑**上，不是开发板上；开发板那一侧完全不变（还是 `ladpd` 接收 + `demo` 播放）。

### 2.2 板上运行

```bash
ssh root@172.20.120.220
cd /root/lvgl-demo

./ladpd -d          # 后台起接收服务（-d 自己 fork 到后台）
./demo              # 正常流程：开机动画 → 登录 → 广告机
```

> **只能有一个界面程序在跑（demo 或 weather）。**
> 两个进程会同时往 `/dev/fb0` 画各自的界面，屏幕上就变成"启动动画的字压在广告机卡片上、
> 底下还在滚公告"那种鬼样子 —— 看着像 UI 错乱，其实是进程打架。
> 现在 `main()` 开头用 `flock(/tmp/lvgl-fb.lock)` 做了单实例保护（demo 和 weather 共用这把锁），
> 第二个实例会直接退出并打印正在跑的 PID：
>
> ```
> [demo] 已经有一个界面程序在跑（PID 2150）。两个进程会同时往 framebuffer 画，
>        屏幕会变成两套 UI 叠在一起。先结束旧的再启动：
>        pkill -9 demo; pkill -9 weather
> ```

**时间**：板子没有 RTC 电池，断电后系统时间会退回 1970/2015，界面上那个钟就完全是错的。
三个地方一起兜：

| 时机 | 做法 |
|---|---|
| `make deploy` | 用本机 UTC 时间 `date -s` 校一次 |
| 客户端连上（任何命令） | 自动发 `TIME <epoch>` |
| 还没校时 | 时钟显示 `--:--` + `等待校时`，而不是一个错的时间 |

显示走 `TZ=CST-8`（程序里 `setenv` + `tzset`），所以是北京时间。

调试时可以跳过前面几幕，省得每次点触摸：

```bash
./demo --login            # 跳过开机动画，直接到登录页
./demo --autologin        # 进登录页后自动用内置账号登录一次（验证跳转用）
./demo --ad               # 跳过动画和登录，直接进广告机
ADVERT_PAGE=lib ./demo --ad    # 直接起在「广告库」页
ADVERT_PAGE=info ./demo --ad   # 直接起在「信息」页
ADVERT_FULLSCREEN=1 ./demo --ad  # 启动 1.5 秒后自动进全屏
ADVERT_DEBUG=1 ./demo --ad     # 每秒打印实际播放帧率
ADVERT_FS_ZOOM=256 ./demo ...  # 强制全屏缩放比（256=1.0 倍，调试用）
ADVERT_TAP=400,200 ./demo --ad # 2 秒后模拟点一次 (400,200)，验证点击链路
ADVERT_TAP=400,200,3000 ./demo --ad   # 指定第 3 秒再点（可配合上面几个测时序）
ADVERT_SWIPE=600,240,180,240 ./demo --ad   # 模拟从右往左划（切下一条）
ADVERT_SWIPE=200,240,620,240 ./demo --ad   # 模拟从左往右划（切上一条）
```

内置账号：`admin` / `123456`（也可以在登录页自己注册）。

### 2.3 让电脑能传素材

客户端要调 ffmpeg 做转码。本机没有系统级 ffmpeg，静态版放在 `~/tools/`：

```bash
cd /home/user/code/lv_port_pc_vscode-release-v8

./advert/tcp/adclient.py ping
#   OK LADP/1 root=/root/lvgl-demo/advert
#   OK PONG
```

找不到 ffmpeg 时用 `FFMPEG=/path/to/ffmpeg` 指定，或 `sudo apt install ffmpeg`。

**任何一条客户端命令都会顺带把电脑的时间推给板子**（LADP 的 `TIME` 命令）。
板子没有 RTC 电池，这是它唯一的授时来源 —— 只要跑过一次客户端，右上角的钟就是准的。
看时间不对，随便跑一条就行：

```bash
./advert/tcp/adclient.py ping      # 顺带校时
```

## 3. 客户端用法

### 3.1 网页上传（给客户用这个）

```bash
make web
# 浏览器打开 http://localhost:8080
```

页面上就这么几步：填标题 → 填备注 → 把视频拖进去 → 把封面图拖进去 → 点「上传到广告机」。
进度条会依次走「转码中 → 上传中 → 完成」，完成后右边列表立刻多一条。
列表里的「删除」按钮也能直接把广告从板上撤下来。

- 视频、封面都是可选的：**只传图**就是图片广告（停留秒数可调），**只传视频**会自动取首帧当封面
- 帧率、停留秒数藏在「高级选项」里，客户不点开就不会被吓到
- 页面用纯标准库实现，客户机器上只要有 python3 就能跑，不用装 Flask

接口一览（想自己接系统也能用）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/ping` | 板子通不通 |
| GET | `/api/list` | 板上现有广告（含备注） |
| POST | `/api/upload` | multipart：title / subtitle / remark / video / cover / fps / hold |
| GET | `/api/status?id=` | 转码+上传进度 |
| POST | `/api/delete` | body：`id=xxx` |

### 3.2 命令行方式（批量/脚本用）

`adclient.py` 的 `--host` 默认就是 `172.20.120.220`，端口 9500。

### 传一条新广告（视频）

```bash
./advert/tcp/adclient.py push \
    --id 04_new --title "夏日新品 · 冷萃咖啡" --sub "SUMMER COLD BREW" \
    --video ~/videos/coffee.mp4 --cover ~/pics/coffee.png
```

它会：抽帧 → 转成 704×312 的 JPEG 序列 → 生成封面和缩略图 → 写一行清单 →
按 `media/<id>/…` 逐个上传 → 最后才传 `meta/<id>.conf`。
**板上 1 秒内自动刷新**，不用重启程序。

### 传一条纯图片广告

```bash
./advert/tcp/adclient.py push --id 05_poster --title "端午海报" \
    --sub "DRAGON BOAT" --cover ~/pics/poster.jpg --hold 6
```

`--hold` 是停留秒数，6 秒后切下一条。

### 只打包不上传

```bash
./advert/tcp/adclient.py pack --id 04_new --title "..." --video a.mp4 --out ./pkg
# 产物 ./pkg/04_new/{cover.jpg, thumb.jpg, f_000.jpg…, meta.conf}
```

打完的目录可以 `push --from` 直接推，也可以 U 盘拷到板上，手工摆成
`media/<id>/` + `meta/<id>.conf` 就行。

### 查看 / 删除

```bash
./advert/tcp/adclient.py list          # 列出板上所有广告
./advert/tcp/adclient.py rm --id 04_new
```

### 改屏幕底部那条滚动公告

```bash
./advert/tcp/adclient.py ticker --text "公益广告 · 关爱老人，从陪伴开始"
./advert/tcp/adclient.py ticker --reset      # 删掉自定义文案，恢复内置默认
```

文案落在 `<素材根目录>/ticker.conf`，程序不写死。板上每秒 stat 一次这个文件，
改了 1 秒内就会滚动新内容，不用重启也不用重新打包。

### 整棵树同步（换板子 / 批量恢复）

```bash
./advert/tcp/adclient.py push-tree --dir advert/data
```

### 常用参数

| 参数 | 说明 |
|---|---|
| `--fps 12` | 抽帧帧率。6818 上 12fps 是稳的，15fps 勉强 |
| `--hold 5` | 图片广告停留秒数 |
| `--fit auto\|cover\|pad\|blur` | 封面裁切方式，见下 |
| `--sub` | 英文副标题，显示在中文标题下面 |

`--fit` 的取值（默认 `auto`）。**封面和每一帧视频都用同一套规则**，
所以不会出现"封面完整、一播起来人被切成两半"：

- `cover`：等比放大铺满再居中裁。横图、竖图适用，画面有张力。
- `pad`：等比缩到装得下，四周用**素材四角的平均色**填满。方形 / 竖屏素材必须用这个，
  否则硬裁成 2.26:1 只剩中间一条。白底图填出来就是纯白，看不出边界。
- `blur`：模糊底 + 完整主体。有氛围感，但素材本身是纯色底时会出现一条接缝。
- `auto`：长宽比在 0.92~1.08 之间（接近正方形）走 `pad`，其余走 `cover`。

## 4. 界面设计

### 4.1 整体结构

```
┌──────────────────────────────────────────────────────────────┐
│ DEEPSEEK          [播放] [广告库] [信息]         02:39        │  顶栏 60px
│                                              1月1日 周四     │
├──────────────────────────────────────────────────────────────┤
│   ┌────────────────────────────────────────────────┐  ┌────┐ │
│   │                                                │  │全屏│ │
│ ◀ │          广告画面 704 x 312（整幅铺满）          │  └────┘ │
│   │                                                │         │
│   └────────────────────────────────────────────────┘         │
│   臻蓝系列 · 机械腕表                            01 / 03      │
│   BLUE SERIES 8500                                ● ● ●       │
├──────────────────────────────────────────────────────────────┤
│ [公益] 公益广告 · 节约用水，从点滴做起 · 文明出行…（循环左移）  │  30px
└──────────────────────────────────────────────────────────────┘
```

- **左上角品牌**：只有 `DEEPSEEK` 一个字标（Montserrat 26px + 3px 字距），
  没有 logo 图形。
- **播放页**：整幅素材铺满卡片，左右浮动箭头手动切，底部 3px 薄荷绿进度条，
  右下角指示点。切广告时一次「白闪溶解」（盖一层白再淡出），把切换藏进光里。
  **点画面任意处（箭头除外）进全屏**，右上角还有个「全屏」小标签提示。
  **左右滑动可以切上一条 / 下一条**（全屏里也能划）。
- **全屏**：铺黑底，把当前帧**完整**放进 800×480 —— 缩放比取宽高两个方向的
  **较小者**（contain），短边留黑边，一点内容都不切。点任意处退出；左右划切广告。
  进全屏时那句「点击任意处退出全屏」2.2 秒后自己淡出。
- **广告库**：3 列自适应网格，每条一张卡片：缩略图 + 类型角标（视频=薄荷绿，
  图片=琥珀色）+ 标题。点卡片直接跳到那条播放。超过 6 条竖向滚动。
- **信息页**：设备参数、本机 IP、监听端口、可用空间、素材目录；
  底部「重新扫描」「退出登录」，以及图片停留秒数的 −/+ 调节。
- **底部滚动公告**：屏幕最底下 30px 一条，左边「公益」角标，右边文案循环左移。
  文案可远程改（见 3.x 的 `ticker` 命令），板上 1 秒内跟着变。

### 4.2 配色与字号

| 用途 | 色值 |
|---|---|
| 背景 | `#F4F7F9` 冷白 |
| 卡片 | `#FFFFFF` + 1px `#E7EEF3` 描边 |
| 主文字 | `#1F2A33` |
| 次文字 | `#5A6B7A` / `#93A3B1` |
| 强调色 | `#3EBFB0` 薄荷绿（唯一强调色） |

中文四级：14 / 16 / 20 / 24px。层级主要靠**颜色和留白**拉开，不靠描边和阴影。

### 4.3 为什么这么克制

6818 没有 GPU，LVGL 是纯软件渲染 —— 每一次圆角、每一层阴影、每一块半透明，
都是 CPU 逐像素算出来的。这台板子上：

- 一张 704×312 的 JPEG 解码 + 全屏刷新 ≈ 80ms
- 加大面积阴影或半透明遮罩，帧率立刻掉到个位数

所以最终只保留了一处动效（换片白闪），卡片用 1px 描边代替阴影，
强调色只出现在激活态和进度条上。**克制不是审美偏好，是这台机器的物理限制。**

## 5. 代码原理

### 5.1 数据流

```
 电脑 (WSL)                                          开发板
┌──────────────────┐                          ┌──────────────────────┐
│ 视频/图片         │                          │ /root/lvgl-demo/     │
│   ↓ ffmpeg       │      LADP over TCP       │   advert/            │
│ 704×312 JPEG 帧   │  ───────────────────▶    │   ├── meta/*.conf    │
│ + cover + thumb   │      ladpd:9500          │   └── media/<id>/    │
│ + 一行 meta       │                          │        ↓             │
└──────────────────┘                          │   ad_store 每秒 stat  │
                                              │        ↓             │
                                              │   advert_ui 重建界面  │
                                              └──────────────────────┘
```

### 5.2 一条广告就是一个目录 + 一行清单

```
/root/lvgl-demo/advert/
├── meta/01_watch.conf        V|臻蓝系列 · 机械腕表|BLUE SERIES 8500|12|5
└── media/01_watch/
    ├── cover.jpg             704×312  封面
    ├── thumb.jpg             232×130  广告库缩略图
    └── f_000.jpg …           704×312  视频帧（图片广告没有这些）
```

清单一行六个字段：

```
类型 | 标题 | 副标题 | 帧率 | 图片停留秒 | 备注
 V   | ...  | ...     | 12   | 5          | 客户A / 双十一档期
```

最后一段「备注」是网页上传时客户填的那句话，会显示在广告库的标题下面。
老清单只有五段，解析时第 6 段取到空串，向后兼容。

**为什么不用一张中心化的 playlist？**
因为客户端要能随时增删广告。如果所有人改同一张表，就得处理「读-改-写」的竞态；
现在每条广告一个 `.conf`，文件名就是顺序（`01_`、`02_`…），
新增 = 多一个文件，删除 = 删一个文件，天然无冲突。
界面按文件名排序就是播放顺序。

### 5.3 视频为什么是 JPEG 帧序列

6818 的 rootfs 里没有 ffmpeg、没有 SDL、Linux 3.4 也没有 V4L2 硬解节点。
要播 H.264 就得把整个 ffmpeg 交叉编译进去（几十 MB），
而且纯软件解码 800×480 在 A53 上跑不到 15fps。

换成 JPEG 帧序列之后：

- 板上只需要 LVGL 自带的 `tjpgd` 解码器（`lv_conf.h` 里 `LV_USE_SJPG 1`）
- 每帧独立，可以随机跳转，传一半断了也不影响已经传好的帧
- 想降帧率直接删几帧，不用重新编码
- 12fps × 704×312 × 约 22KB/帧 ≈ **270KB/秒**，一条 10 秒广告 2~3MB

实测：`ADVERT_DEBUG=1 ./demo --ad` 报 **12 帧/秒（目标 12）**，能稳稳跟上。
15fps 时会掉到 13~14，所以默认就定 12。

### 5.4 播放循环

`play_timer_cb` 是一个 LVGL 定时器，周期 = `1000 / fps`：

```
到点 → frame++ → 取 media/<id>/f_%03d.jpg → lv_img_set_src("A:" + 路径)
     → 更新进度条宽度
     → 如果 frame >= frame_count，换下一条
```

- `A:` 是 LVGL 文件系统的盘符（`LV_USE_FS_STDIO` 配的），`A:/root/x.jpg`
  实际就是 `fopen("/root/x.jpg")`
- 图片广告没有帧，用 100ms 的定时器累计停留时间，到 `hold` 秒就切
- 解码性能不够时定时器会自然延后，表现为帧率下降而不是卡死

### 5.5 LADP 协议

一条 TCP 连接上顺序发多条命令，全文本行 + 可选的二进制体。故意做得极简，
用 `nc` 都能手搓：

| 方向 | 内容 |
|---|---|
| C→S | `HELLO` |
| S→C | `OK LADP/1 root=/root/lvgl-demo/advert` |
| C→S | `PUT <字节数> <crc32> <相对路径>\n` + 原始字节 |
| S→C | `OK 写入 22321 字节 -> media/01_watch/f_000.jpg` |
| C→S | `MKDIR <路径>` / `RM <路径>` / `LIST` / `PING` / `BYE` |
| C→S | `TIME <unix 时间戳>` → 校准板上系统时钟 |
| S→C | `OK …` 或 `ERR <原因>`（出错不断连接，可以继续发下一条） |

几个设计点：

- **路径安全**：只接受相对路径，含 `..` 或以 `/` 开头一律拒绝，防止客户端把文件写到
  素材目录外面去。
- **CRC32 校验**：客户端算 `zlib.crc32`，服务端用同一张表（IEEE 802.3）重算，
  不一致就丢掉重传 —— 串口/WiFi 抖动时不会把半截 JPEG 留在板上。
- **原子写入**：数据先落到 `.tmp/xxx.part`，校验通过才 `rename()` 到目标路径。
  `rename` 在同一文件系统内是原子的，所以 LVGL 那边永远读不到「写了一半的封面」。
- **顺序**：客户端先传媒体、最后传 `meta/<id>.conf`。因为界面只认 meta，
  这样它绝不会看到一条「有清单没素材」的广告。

**实测吞吐**：三条广告共 396 个文件、9MB，`push-tree` 一次推完 **1.25 秒**
（约 7.5MB/s，千兆网直连）。同一条连接顺序发完，没有反复握手。

### 5.6 热更新

界面每秒 `stat()` 一次 `advert/meta` 目录：

```
目录 mtime 变了 → 重新扫描全部 .conf
              → 算一遍内容哈希（文件名 + 标题 + 帧率 + 帧数）
              → 哈希变了才重建当前页
```

两个细节：

- 只 `stat` 目录，不遍历文件，每秒开销可以忽略
- 用内容哈希而不是「目录变了就重建」，避免 `touch` 一下就把正在播的视频重置

重扫后会按 `cur_name` 找回刚才播的那条广告，不会跳回第一条。

### 5.7 登录之后的跳转

```
main.c → boot_screen_show(btn_wind) → 登录成功 → show_main_win()
                                                    ↓
                                            advert_ui_show()
```

`my_win.c` 现在只剩一个转接函数，保留 `show_main_win()` 这个名字是为了
不动 `main.c` 和 `login.c` 里的调用点。

信息页的「退出登录」走 `advert_ui_close()` → `btn_wind()`，回到登录页。

### 5.8 全屏为什么要自己解码一遍

这一段是本项目最不直觉的地方，值得单独说。

想法很自然：`lv_img_set_zoom(img, 394)` 把 704×312 放大到 800×480。**结果全黑。**

原因在 LVGL 的两条绘制路径里：

- **变量图像**（`lv_img_dsc_t`，数据就在内存里）→ 解码结果 `img_data` 有值，
  走 `lv_draw_img_decoded()`，缩放/旋转都正常。
- **文件图像**（`"A:/xxx.jpg"`）→ `lv_sjpg` 是逐行解码器，`dsc->img_data` **恒为 NULL**，
  于是落到 `lv_draw_img()` 的"逐行读取"分支 —— 那条分支压根不看 `zoom`。

所以文件源的 JPEG 设缩放等于没设，表现就是黑屏或者原尺寸。

解决办法是绕开这个限制：用 `lv_img_decoder_read_line()` 把一帧解到自己的
缓冲区，再包装成 `LV_IMG_CF_TRUE_COLOR` 的**变量图像**交给 `lv_img`，
缩放就有数据可用了。

```c
lv_img_decoder_open(&d, "A:/xxx.jpg", color, 0);
for(y = 0; y < h; y++)
    lv_img_decoder_read_line(&d, 0, y, w, buf + y * w);   /* 解到自己的缓冲 */
lv_img_decoder_close(&d);

dsc.header.cf = LV_IMG_CF_TRUE_COLOR;   /* 包装成变量图像，zoom 才生效 */
dsc.data      = (uint8_t *)buf;
lv_img_set_src(img, &dsc);
```

另外两个配套动作：

- 进全屏时把卡片那张图 `LV_OBJ_FLAG_HIDDEN` 藏起来。它被全屏层完全盖住，
  但 LVGL 还是会照常解码+绘制 —— 不藏就是每帧解两遍，帧率直接腰斩。
- 每帧换图后 `lv_obj_invalidate(fs_layer)` 整层重画。放大后的图溢出它自己的矩形，
  只失效图片本身会留一圈残影。

**代价**：缓冲区 704×312×4 ≈ 878KB，用 `malloc` 而非 LVGL 内存池，不占 `LV_MEM`。
实测全屏仍然 11~12fps（目标 12），和普通播放几乎没差别 —— 因为 JPEG 解码量没变，
只是绘制像素从 23 万涨到 38 万。

### 5.9 底部滚动公告怎么做的

用 `lv_label` 的 `LV_LABEL_LONG_SCROLL_CIRCULAR`，LVGL 自己会把文字接到尾部无限滚，
不用算偏移、不用手写定时器，滚动速度用 `anim_speed`（30 像素/秒）控制。

一个坑：**这个模式只在"文字比控件宽"时才滚**。文案短的时候它就静止了，
而"轮播"的意思是一直在动。所以 `set_ticker_text()` 会把文案重复一遍、
中间塞几个全角空格，保证总宽一定超过可视区 712px；滚起来之后，
两遍之间的空白正好当分隔符用。

滚动的重绘区域就是这条 712×21 的带子，一帧一万多个像素，对帧率没有影响。

## 6. 踩过的坑

这些不是理论，是这次一个个撞出来的，写在代码注释里也写在这里：

**1. 4:4:4 的 JPEG 解不出来。**
ffmpeg 从 PNG 转 JPEG 时默认保留全色度（4:4:4），文件合法、电脑上能看，
但 LVGL 的 `tjpgd` 会**静默失败** —— 图片区域一片空白，日志里一个字都没有。
所以 `adclient.py` 里每个 `-vf` 后面都硬编码了 `-pix_fmt yuvj420p`。
症状很迷惑：同样的代码，有的图能显示有的不能，区别只在源文件是 jpg 还是 png。

**2. 说明文字里的「·」变成了空方块。**
GB2312 里的间隔号是 U+30FB(・)，输入法打出来的是 U+00B7(·)，两个码点长得一样。
`gen_fonts.sh` 里显式补了 `·—–` 三个。

**3. LVGL 的慢速断言。**
`LV_USE_ASSERT_MEM_INTEGRITY` 和 `LV_USE_ASSERT_OBJ` 默认是开的，
每次内存分配都遍历整块内存池。在这一帧一张 JPEG 的负载下吃掉三成以上 CPU，
投产必须关。同理 `LV_USE_PERF_MONITOR` / `LV_USE_MEM_MONITOR` 的角标会直接压在广告上。

**4. 堆要够大。**
`LV_MEM_SIZE` 从 4MB 提到 16MB。一张 800×480 的 32bpp 解码缓冲就是 1.4MB，
4MB 池子解两帧就 malloc 失败，表现同样是「图不显示、无报错」。

**5. 千万别在事件回调里删自己。**
切页、重建、退出这些操作如果在按钮的 `LV_EVENT_CLICKED` 里直接
`lv_obj_clean()` 掉自己所在的容器，就是标准的 use-after-free。
`advert_ui.c` 里统一走 `defer_call()`：置一个标志 + 建一个 20ms 的一次性定时器，
等这一轮事件处理完再动手。

**6. 正方形素材不能硬裁。**
1:1 的海报硬裁成 2.1:1，等于把中间一条放大两三倍，只剩半张脸。
走了 `pad`：等比缩进去，四周用四角平均色填满。

**7. 文件源的 JPEG 设了 zoom 也不放大。**
`lv_sjpg` 是逐行解码器，`img_data` 恒为 NULL，LVGL 的缩放路径根本拿不到整幅像素，
于是静默地按原尺寸画（更常见的是整张画到屏幕外、全黑）。
全屏就是这么黑了两次才定位到的，详见 5.8。

**8. `lv_img_set_src` 之后不能立刻量宽高。**
它只是记下尺寸并标脏，真正的 resize 要等一次布局。紧接着 `lv_obj_get_width()`
拿到的是 0，缩放比和居中全部算错。要先用 `lv_obj_update_layout()` 走一遍布局。

**9. `lv_obj` 默认是"可点击"的，透明容器会把点击全部吃掉。**
`lv_obj_create()` 出来的对象默认带 `LV_OBJ_FLAG_CLICKABLE`（`lv_obj.c:436`），
而 `lv_img` / `lv_label` 的构造函数会自己清掉这个标志 —— 于是很容易误判：
"图都不挡点击啊"。

但项目里那些铺满整块的**容器**（换片白闪遮罩 `flash`、进度条 `prog`）是裸
`lv_obj`，它们压在图片上面，先把点击吃走了。LVGL 的事件默认不冒泡，
所以父控件的 `CLICKED` 永远收不到 —— **"点广告进全屏"失效就是这么来的**。

修法：`mk_obj()` 里统一 `lv_obj_clear_flag(o, LV_OBJ_FLAG_CLICKABLE)`，
让容器默认"透明"；真正要点的（页签、按钮、箭头、卡片、全屏层）在建完之后
自己 `lv_obj_add_flag(CLICKABLE)`。广告库里点卡片跳转之前也是被角标挡住的，
这次一起好了。

**10. 改完交互一定要用真点击验证，别只调函数。**
板上没法注入触摸，所以 `main.c` 里挂了一个假指针设备
`ADVERT_TAP=x,y[,ms]`：走 LVGL 自己的命中测试 → 最上层可点对象 → PRESSED →
RELEASED → CLICKED，和真手指同一条路径。上面那个"透明容器吃点击"的问题，
用 `ADVERT_FULLSCREEN=1` 直接调函数是**永远发现不了**的 —— 这也是它第一次
交付时漏掉的原因。

**11. 两个 demo 实例会把界面画成两套叠在一起。**
启动动画的字压在广告机卡片上、底部公告还在滚、右上角时钟也在 —— 看着像布局崩了，
其实是两个进程各画各的。两个进程都 open 着 `/dev/fb0`，谁后画谁覆盖，
没覆盖到的区域就留着另一个的像素。现在有 `flock` 单实例锁兜住。

**12. 部署了新 `ladpd` 但没重启，新命令等于不存在。**
`make deploy` 只是把二进制拷过去，板上跑着的还是旧进程。加了 `TIME` 命令后
客户端发了也纹丝不动，查了半天才发现板上 `ladpd` 的启动时间是几小时前。
现在 `make deploy` 会顺手把 `ladpd` 重启掉。

**13. 加了新文案就要重新生成字库。**
14px / 24px 是按"界面里实际用到的字"裁过的（为了省 flash）。
写了一句新的「等待校时」，结果"校"字显示成空方块 —— 因为没跑 `gen_fonts.sh`。
16px / 20px 是 GB2312 全集不受影响。**改了中文文案就跑一次字库脚本**。

**14. 封面用 pad、视频帧用 cover，同一条广告自己打自己。**
`make_cover()` 早就会按长宽比选 pad/cover，但 `make_video_frames()` 里写死了
cover。于是方形素材出现"封面是完整的人、一播起来只剩半张脸"。
现在 `resolve_fit()` 只算一次，封面和每一帧都用同一个值。

**15. LVGL 的手势在这个负载下根本发不出来。**
`LV_EVENT_GESTURE` 要同时满足"往上找不到可滚动祖先"和"每次采样位移大于
`gesture_min_velocity`"。而这块板子每帧解码一张 JPEG 要 80ms，触摸采样被拖到
100ms 一次，中间的分支互相打架 —— 实测能打印出 `vect=(-133,0)`，
GESTURE 却一次都没发。
最后不用它的手势，自己在 `PRESSED/PRESSING/RELEASED` 里累加位移，
松手时判断横向够不够 70px。顺带解决另一个坑：**LVGL 划完不会抑制 CLICKED**
（`indev_proc_release` 只看 `scroll_obj`），不自己拦一下，划完会顺手进全屏。

## 7. 常用排错

**看板子上到底有没有跑起来**（无显示器时直接抓 framebuffer）：

```bash
ssh root@172.20.120.220 'dd if=/dev/fb0 bs=1536000 count=1' > fb.raw
ffmpeg -f rawvideo -pix_fmt bgra -s 800x480 -i fb.raw shot.png
```

`fbdev` 用的是 32bpp、`xoffset=yoffset=0`，所以前 800×480×4 字节就是当前画面。

**传完不刷新？**
看 `meta/<id>.conf` 有没有真传上去（`adclient.py list` 能看到），
再看 `advert/meta` 的 mtime 有没有变。

**帧率不够？**
`--fps 10` 重新打包，或者把 `CARD_W/CARD_H` 调小（要同时改 `advert_ui.c` 和
`adclient.py` 两处常量，它们必须一致）。

**想清空所有广告？**

```bash
./advert/tcp/adclient.py list          # 先看有哪些
./advert/tcp/adclient.py rm --id 01_watch   # 一条条删
```
